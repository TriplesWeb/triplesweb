# 멤버 상세 페이지 및 콘텐츠 연동 검토 체크리스트

이 브랜치는 `main`을 기준으로 풀코드 검토 및 구현을 진행하기 위한 검토용 브랜치입니다.

## 구현 목표

1. **멤버 상세 페이지와 미디어 태그**
   - 미디어 등록 시 아티스트 태그 선택
   - 개별 멤버 태그를 해당 멤버 상세 페이지와 연결
   - tripleS 단체 태그는 개별 멤버 상세 페이지에 연결하지 않음

2. **멤버별 오브젝트 목록**
   - 멤버 상세 페이지에서 해당 멤버의 오브젝트 목록 조회
   - 전체 목록을 확인할 수 있는 상세 이동 또는 페이지네이션 적용
   - 페이지당 약 20개 항목 표시

3. **오브젝트 상세·찜하기·거래/교환 연동**
   - 오브젝트 상세 페이지
   - 로그인 사용자별 찜하기 기능 및 중복 처리
   - 거래게시판/교환게시판 글 작성 시 오브젝트 선택
   - 선택한 오브젝트의 이미지·정보를 게시글에 표시하고 데이터 관계 저장

4. **앨범 트랙 재생 링크**
   - 각 트랙 제목 오른쪽에 재생 버튼 배치
   - YouTube 또는 Melon의 해당 곡으로 연결
   - 링크가 확인되지 않는 트랙은 잘못된 주소를 임의로 생성하지 않음

5. **멤버·스케줄·미디어 연동**
   - 스케줄 등록/수정 시 관련 멤버 선택
   - 멤버 상세 페이지에서 멤버 관련 스케줄과 미디어 표시
   - 스케줄과 미디어의 관계는 실제 도메인 모델을 확인한 뒤 설계

## 코드 검토 시 확인할 항목

- 기존 패키지 구조, 엔티티, DTO, 서비스, 리포지토리, 컨트롤러의 일관성
- 현재 인증·인가 및 관리자 권한 검사
- 데이터베이스 관계와 기존 데이터 마이그레이션 영향
- API 응답, 입력 검증, 오류 처리 및 보안
- Mustache 템플릿의 실제 모델 키와 프런트엔드 동작
- 페이지네이션 성능, N+1 쿼리 가능성, 중복 찜하기 방지
- 빌드와 테스트 결과

## 진행 원칙

- 이 체크리스트만으로는 기능 구현이 완료된 것이 아닙니다.
- 현재 애플리케이션의 전체 소스와 기존 동작을 검토한 다음, 기능별로 작은 변경을 적용합니다.
- 비밀번호, API 키, DB 접속 비밀값, 업로드 파일 등 비밀정보·대용량 산출물은 커밋하지 않습니다.
- 각 변경은 빌드/테스트와 실제 스키마를 확인한 후 검증합니다.
