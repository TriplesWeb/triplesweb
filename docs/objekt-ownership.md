# 오브젝트 시리얼 조회와 발행량

- 시리얼→토큰: [Objekt Tracker 공개 API](https://objekt.top/api/v1)의 `GET /collections/{slug}/serials/{serial}/transfers`.
- 컬렉션 대조: COSMO `GET /bff/v3/objekts/nft-metadata/{tokenId}`의 Member / Season / Collection 속성.
- 현재 소유자: Abstract RPC의 ERC-721 `ownerOf(tokenId)`를 `latest` 블록에서 조회한다. 인덱스의 소유자 주소만으로 현재 소유자를 확정하지 않는다.
- COSMO 메타데이터 이름의 `#숫자`는 토큰 ID일 수 있다. 이를 시리얼로 해석하지 않는다. 시리얼 매칭은 공개 인덱스 기준이며 인덱스 반영 지연이 있을 수 있다.
- 미제공, 미발견, 소각, 외부 서비스 오류는 구분한다. 외부 API의 `hide: true`만으로 사용자가 비공개를 설정했다고 단정하지 않으며 추가 식별을 시도하지 않는다.
- 검증된 지갑의 공개 `/profiles/{address}`와 해당 지갑의 공개 전송 이력에서 닉네임 후보를 찾고, COSMO `by-nickname`의 지갑이 현재 소유 지갑과 일치할 때만 표시한다. 확인된 닉네임은 5분 캐시하며 닉네임 변경·재사용으로 다른 계정을 표시하지 않도록 검증한다. 공개 프로필이 일시적으로 실패해도 검증 가능한 이력 후보를 시도한다.
- 상세 화면의 공개 조회 응답은 상태·시리얼·닉네임·사이트 내부 프로필 링크만 전달한다. 토큰 ID, 지갑 주소, 검증 시각과 탐색기 링크는 프론트에 전달하거나 표시하지 않는다.
- 발행량: `GET /collections/rarity`를 시작 1초 뒤부터 5분마다 한 번 호출한다. 완전한 메모리 스냅샷을 교체하며 실패 시 이전 값을 유지한다. 개별 카드/목록 요청에서 외부 API나 DB 전체 재기록을 실행하지 않는다.
- 발행량 미확인은 0으로 취급하지 않으며, 많은순/적은순 모두 마지막에 배치한다. 동률은 slug/id로 정렬하여 페이지 순서를 일정하게 유지한다.

설정: `objekt.api.base-url`, `cosmo.api.base-url`, `abstract.indexer.rpc-url`, `abstract.indexer.contract`, `objekt.mints.refresh-ms`, `objekt.mints.initial-delay-ms`.
기존 전체 Transfer 인덱서는 활성화할 필요가 없다. DB 스키마 변경도 없다.

찜은 기존 브라우저 세션 기준이다. 추가·해제는 명시적인 상태를 저장하고, UUID/slug/collectionId로 저장된 기존 찜을 함께 인식·해제한다. 목록에서 없어진 카드도 찜 목록에서 삭제할 수 있다.

## 내 오브젝트 검색

헤더 코스모 메뉴의 두 번째 항목은 `/cosmo/collection`이다. 닉네임은 COSMO에서 확인하며,
없는 계정(404) 또는 빈 닉네임 제출에는 `없는 닉네임 입니다.`를 표시한다. 서버 장애와 구분한다.
보유 목록은 공개 인덱스의 `GET /objekts/owned-by/{address}`에서 시리얼과 이미지 메타데이터를 묶어서 받는다.
`nextCursor`가 있으면 마지막 페이지까지 읽고 토큰 기준으로 중복을 제거한 뒤 10분 캐시하고,
화면은 24장씩 표시한다. 페이지를 넘길 때마다 체인 로그와 개별 토큰 메타데이터를 다시 조회하지 않는다.
이 목록은 인덱스 반영 지연과 최대 10분 캐시 지연이 있을 수 있다.
카드 제목의 토큰 ID 접미사는 제거하고 실제 `serial`을 표시한다. 시리얼 미제공 시 `시리얼 확인 중`으로 안내하며 번호를 추측하지 않는다.

## 닉네임 상세

`/cosmo/profile/{nickname}`에서 닉네임·프로필 이미지·보유 개수·중복 제외 종류 수와 멤버 수를 표시한다.
소유자 조회 결과와 내 오브젝트 검색 결과에서 연결한다. 지갑 주소나 토큰 ID는 표시하지 않는다.
`tab=collection`은 멤버 필터와 24장 페이지를 지원하며 같은 보유 목록 캐시를 사용한다.
`tab=progress`는 tripleS 멤버별 수집률과 전체 보유 목록의 시즌·클래스 분포를 표시한다.
멤버 수집률은 Welcome·Zero를 제외하고, 현재 카탈로그 종류 집합과 실제 보유 종류 집합의 교집합 / 전체 카탈로그 종류 수로 계산한다.
중복 카드는 수집률을 올리지 않으며 카탈로그 미적재 시 수집률을 만들지 않고 목록 준비 중으로 안내한다.
이는 공개 인덱스·현재 카탈로그 기준의 현황이며 다른 사이트의 포함·제외 기준과는 다를 수 있다.

`tab=progress&member=YuBin`처럼 멤버를 선택하면 보유하지 않은 종류까지 포함한 수집 목록을 표시한다.
현재 카탈로그를 시즌·클래스로 묶고, 각 클래스 안에서 collectionNo의 숫자 부분을 오름차순 정렬한 뒤 접미사·slug로 동률을 정리한다.
보유 판정은 시리얼이나 토큰 ID가 아닌 컬렉션 slug 집합으로 수행한다. 보유 카드는 밝게, 미보유 카드는 어둡게 표시하며 글자 배지도 함께 제공한다.
클래스별 목록은 펼치기/접기가 가능하고 완료한 시즌을 숨길 수 있다. 사진은 contain으로 표시하고 지연 로딩한다.
한 장도 보유하지 않은 멤버도 현재 카탈로그의 멤버 선택 목록에서 열 수 있다.

## 공통 필터 순서

오브젝트 목록, 교환·판매 글의 작성/수정 선택창, 닉네임 상세의 멤버 선택은 `ObjektFilterOrder`를 공유한다.
멤버는 S1~S24 순서이며 영어 이름·한국어 이름·S 번호를 같은 멤버 순위로 취급한다.
교환 글·프로필의 유닛/기타 선택값은 S24 뒤에 ABC·가나다순으로 배치하며 `S1 X S9`를 S1 솔로로 정렬하지 않는다. 메인의 조합·기타 분류는 아래와 같이 별도로 제공한다.
사진 없는 항목과 사진 로딩에 실패한 메인 오브젝트 필터는 글자 버튼으로 유지한다.
시즌은 Cream02 → Binary02 → Atom02 → Ever01 → Divine01 → Cream01 → Binary01 → Atom01 순서다.
세대 번호와 Atom/Binary/Cream/Divine/Ever 순환 순위로 비교하며 알 수 없는 시즌은 알려진 시즌 다음에 이름순으로 배치한다.
원본 카탈로그 데이터는 유지하며 멤버 선택값과 표시는 한글 이름으로 통합한다.
예를 들어 S21/ChaeWon/채원/김채원은 `김채원` 옵션 하나가 되고, S22는 `설린`, S23은 `서아`, S24는 `지연`만 표시한다.
검색과 프로필 수집 집계에서도 같은 별칭을 합치며 기존 S 번호·영문 쿼리 URL의 검색과 선택 상태를 유지한다.
수집 목록의 시즌 구역도 같은 최신순을 사용한다.

메인 `/cosmo/objekt`의 멤버 피커에는 조합·기타 버튼을 따로 나열하지 않는다.
`S5 X S20`의 오브젝트는 김유연 또는 박시온 중 하나라도 선택하면 검색되며 여러 명을 선택해도 중복 표시하지 않는다.
번호 조합을 단일 멤버와 구분해 해석하므로 S1/S10, S2/S20은 서로 겹치지 않는다.
`group=all`은 전체, `group=members`는 알려진 멤버와 연결된 오브젝트, `group=other`는 그 외 그룹·기타 오브젝트다.
기타 탭으로 전환하면 멤버 선택을 지우고, 시즌·클래스·검색어는 유지한다. 추가 로딩도 동일한 group 필터를 사용한다.
분류는 원본 member/memberName의 공개 이름·번호 조합을 기준으로 하며, 같은 원본 값은 요청 내에서 한 번만 해석한다.
