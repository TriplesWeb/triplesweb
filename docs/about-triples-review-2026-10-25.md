## 3. 우선 수정할 코드 문제

### C01. 케미 설명 HTML 정제 누락 — 높음 / 코드 확인

자체 정제 함수에서 `B`, `STRONG`, `I`, `EM`, `U`, `BR` 등의 속성이 제거되지 않는다. 허용하지 않은 태그를 벗겨내는 분기에서도 옮겨진 자식 노드를 다시 검사하지 않는다. 이벤트 속성이나 중첩된 위험 요소가 정제 결과에 남을 수 있다. 설명은 서버에서 그대로 저장되고 화면에서 HTML로 삽입되므로 저장형 XSS 경로가 된다. 관리자 입력 전용이어도 외부 HTML 붙여넣기·계정 탈취와 결합될 수 있다.

- 개선: 서버 정제와 검증된 HTML 정제 라이브러리 사용. 태그·속성·URL 프로토콜을 명시적으로 제한.
- 검증 기준: 이벤트 속성, 중첩 비허용 태그, 잘못된 URL을 모두 제거하는 회귀 테스트.
- 근거: `src/main/resources/static/js/chemistry.js:554`, `src/main/java/com/example/triplesweb/service/ChemistryService.java:77`, `src/main/java/com/example/triplesweb/service/ChemistryGroupService.java`.

### C02. 세션·쿠키 인증을 사용하는 변경 API의 CSRF 방어 — 높음 / 코드 확인

전역 CSRF 검사가 비활성화되어 있고 관리자 권한은 세션·쿠키로도 인정된다. 실제 악용 가능성은 배포 환경의 쿠키 정책·출처 조건에 영향을 받지만, 변경 요청의 명시적 CSRF 검증이 필요하다.

- 개선: 관리자 변경 API에 CSRF 토큰 검증 적용. 출처 검증과 쿠키 정책 병행.
- 근거: `src/main/java/com/example/triplesweb/SecurityConfig.java:18`, `src/main/java/com/example/triplesweb/service/AboutAdminAuth.java`.

### C03. 관리자 토큰 저장·발급·폐기 — 높음 / 코드 확인

- 토큰을 localStorage와 JavaScript 쿠키에 함께 저장하여 XSS 발생 시 탈취 가능.
- 로그아웃 폐기 목록이 메모리에만 있어 서버 재시작 후 아직 만료되지 않은 토큰이 다시 유효해질 수 있음.
- 토큰에 고유 난수가 없어 같은 초에 로그인하면 동일 토큰 발급.
- 로그인 시도 제한이 인증 서비스에 없음. 프록시 등 외부 방어 여부는 미확인.

개선: 가능하면 HttpOnly·Secure 세션 쿠키 중심으로 단순화. 별도 토큰은 고유 ID, 지속적인 폐기 관리, 로그인 시도 제한 적용.

근거: `src/main/resources/static/js/about-admin-auth.js:38`, `src/main/java/com/example/triplesweb/service/AboutAdminAuth.java:61`, `:77`, `:135`.

- 개선: 데이터 미존재는 404로 매핑하고 목록 복귀 안내 제공. 운영 예외 상세 비노출 설정 확인.

### C07. 곡 검색 링크 URL 인코딩 누락 — 중간 / 코드·화면 링크 확인

- 개선: 서버에서 인코딩된 검색 URL을 만들거나 URLSearchParams 사용.

### C08. 그룹 소개의 탭 주소 검증 부족 — 중간 / 코드 확인

## 6. 성능·데이터 정확성

### P01. 그룹 소개 요청에서 전체 멤버 피드 구성

그룹 탭만 보더라도 24명 피드를 모두 구성한다. 사진·영상 각 최대 2,000건, 전체 일정, 전체 공식 미디어를 읽고 멤버별 필터링을 반복한다. 오브젝트 원본은 이미 캐시되지만 정렬·분류는 요청마다 수행된다.

- 개선: 선택한 멤버의 피드만 지연 조회하고 결과 캐시. DB에서 필요한 멤버·최신 N건만 조회하거나 일괄 집계.
- 기대 효과: 초기 응답 시간, 서버 메모리·CPU 사용량, HTML 크기 감소.
- 주의: 성능 수치·프로파일링은 이번에 측정하지 않았으므로 개선량을 단정하지 않음.
- 근거: `src/main/java/com/example/triplesweb/service/MemberSpotlightService.java:47`, `src/main/java/com/example/triplesweb/service/MediaService.java:112`.

### P02. 아카이브 최신 5개 정확성

전체 최신 2,000건 안에서 멤버를 찾으므로 그 범위 밖에만 자료가 있는 멤버는 실제 자료가 있어도 없음으로 표시될 수 있다.

- 개선: 멤버 조건으로 먼저 필터링한 뒤 최신 5건 제한. 멤버 연관을 문자열보다 ID 관계로 관리.
- 근거: `src/main/java/com/example/triplesweb/service/MemberSpotlightService.java:60`.

### P03. 숨겨진 탭 이미지 로딩

앨범 목록은 숨겨진 섹션까지 일반 src로 이미지를 제공하고 lazy loading이 없다. 그룹 소개의 숨겨진 멤버 프로필도 동일한 즉시 로딩 구조다. 피드 썸네일에는 일부 lazy loading이 이미 적용되어 있다.

- 개선: 현재 탭 첫 화면 이미지만 우선 로딩. 나머지는 lazy 또는 탭 활성화 시 src 지정. 이미지 크기 예약과 적절한 썸네일 제공.
- 근거: `src/main/resources/templates/triples/album.mustache:49`, `src/main/resources/templates/triples/artist.mustache`.

### P04. 케미 초기 요청의 순차 대기

관리자 상태 → 2인 케미 → 그룹 케미를 순차 대기한다.

- 개선: 독립 요청 병렬화, 그룹 케미는 3인 이상 화면 진입 시 조회, 공개 데이터 오류 재시도 버튼 제공.
- 근거: `src/main/resources/static/js/chemistry.js:2332`.

### P05. Tailwind 런타임 CDN 의존

대상 페이지가 CDN 런타임 스크립트에 의존하고 head 구성도 중복된다.

- 개선: CSS 빌드 결과물을 정적으로 제공하고 공통 head를 partial로 추출. 배포 시 자산 해시 기반 캐시 관리.
- 근거: `src/main/resources/templates/triples/artist.mustache:12` 및 나머지 대상 템플릿.

## 7. 유지보수 구조

- DB·케미 JS·서비스의 멤버 이름·영문명·색상·순서 중복을 멤버 ID 기반 공통 데이터로 통합.
